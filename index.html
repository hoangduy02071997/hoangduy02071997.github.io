Realtime chat

From simple sockets to distributed services.

In a private chat system with millions of messages, I worked with cursor pagination, indexed timestamps, Redis-backed realtime infrastructure, multiple Node.js instances and service communication. The goal was to keep history retrieval and realtime delivery predictable as data and traffic grew.

3M+ messagesCursor paginationRedisWebSocket
01 · Pagination — Replaced offset/limit thinking with cursor-based retrieval for large chat histories.
02 · Database — Used indexed time-based ordering to make message retrieval scale with large datasets.
03 · Realtime — Redis adapter / pub-sub allows socket instances to coordinate across horizontal scaling.
04 · Failure handling — Circuit-breaker thinking prevents unhealthy dependencies from causing repeated waiting and retry costs.
05 · Architecture — Used microservices, gRPC, Kafka and Redis where product requirements justified the added complexity.
